# ADR-004. Доступ к данным агрегатов

**Статус:** принято

## Контекст

Связка, заказ и курьер — агрегаты DDD; правило «заказ ровно в одном состоянии» держится внутри агрегата.

**Вопрос:** Как модуль читает и сохраняет свои агрегаты

**Основание:** Агрегаты доменной модели; D04-S04-NFR002; ДР-9

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| Spring Data JDBC | Один репозиторий на агрегат, без ленивой подгрузки и сессии; агрегат сохраняется целиком | Связи между агрегатами только по идентификатору, отчётные выборки пишутся вручную |
| JPA, Hibernate | Богатое отображение, ленивые связи | Через ленивую связь в одной сессии можно незаметно изменить чужой агрегат |
| jOOQ | Полный контроль над SQL | Нет понятия агрегата, границу держит только дисциплина |

## Критерии

К1 — агрегат сохраняется целиком в одной транзакции; К2 — из одного агрегата нельзя изменить другой. JPA не выполняет К2, jOOQ — К1 и К2

## Решение

Spring Data JDBC.

**Цена решения:** ручные запросы для отчётных выборок ФП-5

## Как проверить

Прототип агрегата «Связка» с одновременной выдачей двух связок
