# Стенд БД

Временный экземпляр PostgreSQL 17 с данными за 90 дней: замеры запросов, миграция схемы v1 → v2 с откатом и нагрузочный тест выдачи направления. Основной сервер PostgreSQL не затрагивается: стенд поднимает свой экземпляр в `pgdata` на порту 55432.

Нужны PostgreSQL 17 (по умолчанию путь Postgres.app, другой задаётся `PGBIN`), python3 и zsh. Займёт около 7 минут и ~7 ГБ на диске.

```bash
./run.sh            # всё сразу
./run.sh clean      # удалить стенд
```

По шагам: `init`, `load`, `bench1`, `migrate`, `bench2`, `rollback`, `reapply`, `nfr001`, `rollback-track`, `stop`, `start`.

## Что внутри

| Файл | Назначение |
|---|---|
| `sql/v1_ddl.sql` | Исходная схема v1 |
| `sql/gen.sql`, `sql/track.sql` | Данные: 3 даркстора, 120 курьеров, 405 тыс. заказов, 12,9 млн точек трека |
| `sql/migrate_up.sql`, `sql/migrate_down.sql` | Миграция v1 → v2 и откат |
| `sql/check.sql` | Контрольные суммы и проверка ограничений |
| `sql/fr027*.sql` | Сценарий выдачи направления для pgbench |
| `bench.py` | Медиана `EXPLAIN ANALYZE` по 7 прогонам для типовых запросов Q1–Q9 |
| `results/` | Результаты замеров |

Генератор данных синтетический и равномерный: он подходит для оценки производительности, но не для аналитических выводов.

## Результаты

| Запрос | v1, мс | v2, мс |
|---|---|---|
| Q1 действующие заказы даркстора | 54,1 | 0,13 |
| Q5T последние точки 100 смен | 3 223 | 0,37 |
| Q6 журнал решений даркстора | 16,9 | 1,33 |
| Q8 трек курьера за 14 дней | 121,4 | 15,6 |

Значения здесь — из одного прогона `bench.py` (`results/bench_v*.json`), поэтому немного отличаются от медиан в [модели данных](../docs/06-data-model.md).

**Выдача направления (NFR001):** pgbench, 10 параллельных курьеров, 60 с — 906 533 транзакции, p50 0,56 мс, p95 1,35 мс, p99 2,57 мс.
