# ADR-003. Серверная платформа модульного монолита

**Статус:** принято

## Контекст

Платформа должна удерживать границы подсистем.

**Вопрос:** На чём строить модульный монолит

**Основание:** Архитектура (docs/04); владельцы данных доменная модель; D04-S04-NFR002; ДР-9

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| Java 21, Spring Boot 3, Spring Modulith | Проверка зависимостей между модулями в тестах сборки; сохранение исходящих событий в транзакции изменения данных и их досылка после сбоя; обе возможности в одном фреймворке | Больший расход памяти и время запуска JVM, зависимость от соглашений фреймворка |
| .NET 8 | Высокая производительность, развитые инструменты | Проверка границ и сохранение событий собираются из сторонних библиотек |
| Go | Малый расход ресурсов, один исполняемый файл | Проверка границ и сохранение событий собираются из сторонних библиотек или пишутся вручную |
| Python, FastAPI | Быстрая разработка | То же, что у Go; типы не проверяются при сборке, что опасно для правил распределения |

## Критерии

К1 — автоматическая проверка границ модулей; К2 — сохранение исходящих событий в транзакции изменения данных; К3 — обе возможности в одном фреймворке. .NET, Go и Python не выполняют К3

## Решение

Java 21, Spring Boot 3, Spring Modulith; модуль соответствует ФП или ОФ.

**Цена решения:** ресурсы JVM, зависимость от компетенций команды

## Как проверить

Тест структуры модулей в сборке падает при обращении одной ФП к внутренним классам другой; подтверждение компетенций команды
