# ADR-011. Входной шлюз

**Статус:** принято

## Контекст

Запросы приложения курьера, панели куратора и рабочего места сети попадают в приложение через периметр.

**Вопрос:** Как запросы трёх систем попадают в приложение

**Основание:** Граница Г1; потоки F-05, F-07, F-08; D04-S01-NFR005

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| nginx | Проверка сертификата клиента, ограничение частоты и балансировка на две копии в одном процессе с файлом конфигурации | Ограничения и маршруты настраиваются вручную |
| Kong | Учёт потребителей и ключей API, плагины | Отличительные возможности при трёх клиентах с сертификатами не используются, плагины добавляют слой сопровождения |
| Spring Cloud Gateway | Тот же язык, что у приложения | Ещё одно приложение на JVM, которому самому нужно резервирование |

## Критерии

К1 — проверка сертификата клиента и ограничение частоты; К2 — балансировка на две копии; К3 — без отдельного приложения или базы конфигурации. Spring Cloud Gateway не выполняет К3; Kong выполняет К1–К3, но его отличие — учёт потребителей — проекту не нужно, поэтому выбран более простой вариант

## Решение

nginx на двух ВМ с общим адресом через keepalived.

**Цена решения:** ручная настройка ограничений

## Как проверить

Подключение без сертификата отклоняется; при отключении копии приложения запросы уходят на вторую
