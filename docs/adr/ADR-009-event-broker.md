# ADR-009. Доставка событий смежных систем

**Статус:** принято

## Контекст

События И-01–И-04 должны доходить до АС без потерь и без повторной обработки.

**Вопрос:** Как события смежных систем доходят до АС

**Основание:** D01-S01-NFR006; D04-S04-NFR002; D01-S04-FR011

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| RabbitMQ | Подтверждение каждого сообщения; встроенная очередь недоставленных сообщений; хранение событий, пока АС недоступна | Перечитать уже обработанные события нельзя |
| Apache Kafka | Хранение истории, большие потоки | Нет встроенной очереди недоставленных: «плохое» событие останавливает чтение или пропускается |
| NATS JetStream | Лёгкость и скорость | Очередь недоставленных собирается вручную |
| Прямые HTTP-вызовы | Нет лишнего компонента | Пока АС недоступна, события теряются |

## Критерии

К1 — событие хранится, пока АС недоступна; К2 — подтверждение каждого сообщения; К3 — встроенная очередь недоставленных для отклонённых событий. HTTP-вызовы не выполняют К1, Kafka и NATS JetStream — К3

## Решение

RabbitMQ на трёх узлах с кворумными очередями. В АС исходящие события сохраняются в реестре Spring Modulith в транзакции изменения данных, входящие сверяются с таблицей обработанных идентификаторов.

**Цена решения:** перечитать историю событий нельзя

## Как проверить

Тест повторной доставки и отключения АС; уточнение у ИТ-подразделения сети наличия корпоративного брокера
