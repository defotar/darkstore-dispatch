# ADR-005. Оперативная база данных

**Статус:** принято

## Контекст

База хранит состояние заказов, курьеров, направлений, связок и журнал решений.

**Вопрос:** Где хранить оперативное состояние кластера

**Основание:** D04-S04-NFR002; D01-S01-NFR006; D05-S02-NFR008; ДР-9; ограничение бюджета 

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| PostgreSQL 16 | Внешние ключи и транзакции через несколько таблиц; частичный уникальный индекс; изменение схемы модуля откатывается целиком; отдельная схема и учётная запись на модуль; открытая лицензия | Резервирование настраивается отдельно |
| MySQL 8 | Открытая лицензия, распространённость | Нет частичных индексов (только обход через вычисляемый столбец); изменение схемы не откатывается транзакцией |
| MongoDB | Гибкая структура документов | Нет внешних ключей между коллекциями |
| Oracle | Высокая надёжность | Платная лицензия; изменение схемы не откатывается транзакцией |

## Критерии

К1 — внешние ключи и транзакции через несколько таблиц; К2 — штатный частичный уникальный индекс, чтобы заказ входил не более чем в одну действующую связку; К3 — открытая лицензия; К4 — неудачное изменение схемы модуля откатывается целиком. MySQL не выполняет К2 и К4, MongoDB — К1, Oracle — К3 и К4

## Решение

PostgreSQL 16; схемы d01–d05 с отдельными учётными записями модулей; журнал решений в схеме d05 с помесячными разделами.

**Цена решения:** резервирование решается в ADR-006

## Как проверить

Две одновременные попытки включить заказ в разные связки: вторая отклоняется индексом

> **Изменение после проверки на стенде.** Помесячные разделы журнала решений сняты: при 200 тыс. строк за 90 дней удаление суток по индексу занимает 12 мс, а разделы требовали копировать время записи в варианты решения (нарушение 2НФ). См. [модель данных](../06-data-model.md).
