# ADR-017. Встроенный кэш Caffeine для времени в пути и ключей токена

**Статус:** принято. Уточняет раздел «Что не нужно» исходного набора технологий: кэш оперативных данных по-прежнему не нужен, но для ответов внешних систем он окупается.

## Контекст

| Данные | Кто и как часто читает | Цена промаха | Как меняются | Решение |
|---|---|---|---|---|
| Время в пути из сервиса маршрутизации | Пересчёт прогноза раз в 20 с для до 100 курьеров и трёх дарксторов; выдача направления — до 20 в минуту | Вызов внешнего сервиса через исходящий шлюз: сотни миллисекунд на пути к лимиту 2 с (NFR001) и зависимость от доступности сервиса | С дорожной обстановкой, за десятки минут | Кэшировать |
| Ключи проверки токена | Каждый запрос API | HTTPS-запрос к серверу учётных записей (И-09) | При смене ключей, редко | Кэшировать |
| Заказы, смены, связки, направления | Все модули постоянно | 0,1–0,6 мс (модели данных v2) | На каждое событие | Не кэшировать: выигрыша нет, а копия в памяти рискует разойтись с БД (NFR002) |
| Справочники и пороги | Пересчёт прогноза | Доли миллисекунды | Редко | Не кэшировать: выигрыш — микросекунды |
| Витрина | Модуль «Контроль сроков» по запросу | Миллисекунды | Раз в сутки | Не кэшировать: запросов единицы в день |

## Варианты: класс решения

| Критерий | Встроенный кэш (библиотека в процессе) | Отдельный сервер кэша |
|---|---|---|
| Где данные | В памяти каждой копии приложения | Один общий набор для всех копий |
| Задержка чтения | Микросекунды, без сети | Доли миллисекунды: сетевой запрос |
| Согласованность между копиями | У каждой копии свой набор, промахи удваиваются | Общий набор, один промах на все копии |
| Отказ | Только вместе с копией приложения | Отдельная точка отказа: нужны реплики и переключение |
| Эксплуатация и защита | Нет нового сервера и сетевого доступа | Новая ВМ или контейнер, мониторинг, ACL, TLS |
| Когда выгоден | Мало данных, мало копий | Много копий или нужен общий лимит запросов к внешней системе |

## Варианты: встроенные кэши

| Критерий | Caffeine 3 | Ehcache 3 |
|---|---|---|
| Типы данных | Объекты Java «ключ — значение» | Объекты Java «ключ — значение»; стандарт JCache |
| Размещение и персистентность | Только память JVM | Память JVM, память вне кучи, диск |
| Фоновое обновление до истечения срока | Есть (refreshAfterWrite) | Нет встроенного |
| Пакетная загрузка и один загрузчик на ключ | Есть (getAll, AsyncLoadingCache) | Через загрузчик CacheLoaderWriter, пакет — отдельной реализацией |
| Вытеснение | W-TinyLFU по числу записей или весу | По размеру яруса, вариант LRU |
| Кластеризация | Нет | Через сервер Terracotta |
| Лицензия | Apache 2.0 | Apache 2.0 |
| Эксплуатация | Подключается в Spring Boot без настройки, метрики Micrometer | Конфигурация XML или Java, метрики через JCache |
| Меры защиты | Данные не покидают процесс | Данные не покидают процесс; на диске — файлы без шифрования |

## Решение

Встроенный кэш **Caffeine 3** в модуле «Местоположение и время в пути»: read-through, фоновое обновление через 12 минут (`refreshAfterWrite`), удаление через 60 минут, один загрузчик на ключ. Ключи проверки токена кэширует Spring Security. Данных меньше 10 МБ, копий приложения две, поэтому отдельный сервер добавил бы точку отказа на пути к лимиту 2 с без выигрыша.

Если копий станет много или понадобится общий лимит запросов к сервису маршрутизации, выбор — **Valkey** (та же функциональность, что у Redis 8, под лицензией BSD).

Подробно: [Кэш и отказы](../09-cache-and-failures.md).
