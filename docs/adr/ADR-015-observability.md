# ADR-015. Наблюдаемость

**Статус:** принято

## Контекст

Нужно видеть нарушение 2 с и разбирать опоздания по журналам.

**Вопрос:** Как контролировать время ответа и разбирать сбои

**Основание:** D04-S02-NFR001; D04-S01-NFR005

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| Prometheus, Grafana, Loki, Grafana Alloy, Micrometer | Распределение времени выдачи направления и оповещение при превышении 2 с; журналы рядом с метриками; агент отправляет данные в одну сторону; Loki индексирует только метки | Слабый полнотекстовый поиск по журналам |
| ELK | Сильный полнотекстовый поиск | Полнотекстовый индекс всех журналов при объёме проекта не нужен и требует в разы больше ресурсов |
| Zabbix | Часто уже используется в компаниях | Не строит распределение времени ответа приложения |

## Критерии

К1 — распределение времени выдачи направления и оповещение при превышении 2 с; К2 — журналы и метрики в одном интерфейсе; К3 — передача из прикладного сегмента в одну сторону. Zabbix не выполняет К1; ELK выполняет К1–К3, но его отличие — полнотекстовый поиск — проекту не нужно

## Решение

Micrometer в приложении, агент Grafana Alloy на ВМ, Prometheus, Loki и Grafana в зоне контроля; координаты в журналы не записываются.

**Цена решения:** ограниченный поиск по тексту журналов

## Как проверить

Искусственная задержка ФП-4 на стенде вызывает оповещение; проверка лицензии AGPL у Grafana и Loki: они используются внутри сети без изменений
