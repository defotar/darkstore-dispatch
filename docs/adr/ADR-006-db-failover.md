# ADR-006. Резервирование базы данных

**Статус:** принято

## Контекст

Отказ сервера базы данных не должен останавливать выдачу направлений.

**Вопрос:** Как база данных переживает отказ сервера

**Основание:** D04-S01-NFR005

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| Patroni и etcd | Автоматическое переключение на реплику; выбор основного сервера через etcd исключает два основных сервера одновременно | Три узла etcd — ещё один компонент |
| Реплика с ручным переключением | Простота | Ночью нужен дежурный, простой длится до его реакции |
| Кластер ОС с общим диском | Одна копия данных | Общий диск — единая точка отказа, нужна отдельная система хранения |

## Критерии

К1 — переключение без участия человека; К2 — два основных сервера одновременно невозможны; К3 — нет единой точки отказа хранения. Ручная реплика не выполняет К1, общий диск — К3

## Решение

Patroni на двух ВМ базы данных, etcd на трёх узлах.

**Цена решения:** сопровождение etcd; переключение при настройках по умолчанию занимает до 30 с, в это время запись недоступна и приложение повторяет её

## Как проверить

Учебное отключение основного сервера на стенде с измерением времени переключения
