# ADR-001. Контракт API для внешних интерфейсов

**Статус:** принято

## Контекст

Приложение курьера, панель куратора и рабочее место сети вызывают функции АС по контракту.

**Вопрос:** Как внешние интерфейсы вызывают функции АС

**Основание:** Интеграции И-05, И-07, И-08; D04-S04-NFR004; у АС нет собственного интерфейса

## Варианты

| Вариант | Достоинства | Недостатки |
|---|---|---|
| REST/JSON с контрактом OpenAPI | Проходит через обычный HTTP-шлюз и вызывается из браузерной панели напрямую; по контракту генерируются клиенты для трёх внешних команд; набор команд фиксирован, права проверяются на каждой операции | Нет встроенной отправки сообщений клиенту |
| gRPC | Строгий контракт, высокая скорость | Двоичный протокол: внешним командам нужны генерация кода и специальные средства отладки, из браузера — прослойка gRPC-Web |
| GraphQL | Клиент сам выбирает нужные поля | Произвольные запросы: права по даркстору приходится проверять на каждом поле |

## Критерии

К1 — вызов и отладка обычными средствами HTTP, в том числе из браузера; К2 — проверка прав на уровне операции; К3 — машиночитаемый контракт для внешних команд. gRPC не выполняет К1, GraphQL — К2; REST/JSON с OpenAPI выполняет все три

## Решение

REST/JSON с отдельным контрактом OpenAPI на каждую интеграцию.

**Цена решения:** отправку сообщения курьеру приходится решать отдельно (ADR-002)

## Как проверить

Внешние команды генерируют клиентов по контракту и проходят контрактные тесты до подключения
